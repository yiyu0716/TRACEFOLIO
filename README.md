# TRACEFOLIO

<!-- Modified from LuJie CareerKit for TRACEFOLIO (2026). See NOTICE and docs/UPSTREAM.md. -->

**有据可循的职业成长。** 面向中国市场程序员与 AI 技术人才的个性化求职 Agent，持续连接职业记忆、真实经历、岗位要求、简历版本与面试复盘。

当前为 **v0.2 开发原型**：本地单用户工作台可打包为 macOS / Windows 桌面应用，另有独立的账号、套餐权益、模型网关和私有资料云服务。证据支撑的 JD 简历定制采用 **Codex app-server + MCP 职业工具 + 独立任务 worker**，通过提案核对后保存新版本。尚未完成生产商用验收，详见 [桌面与云服务说明](docs/DESKTOP_CLOUD.md)。

## 开始运行

需要 Node.js 22+、npm，以及首次安装依赖时的网络连接。

```bash
npm ci
npm run setup
npm run dev
```

打开 [本机工作台](http://127.0.0.1:3000/intelligence)。启动时自动应用 SQLite 数据库迁移。`npm run setup` 会生成不会提交到 Git 的 `.env` 和随机凭证加密密钥；已有文件会保留。

需要 AI 功能时，在设置页选择服务商、模型、Base URL 和 API Key，并测试连接。模型必须支持相应的工具调用 / 结构化输出能力，实际兼容性需要测试。基础记忆、证据、标签覆盖分析和成长计划不需要模型。

设置页可保存、切换多组自带密钥或平台模型连接，登录平台账号、查看 Agent 权益与模型额度，并显式上传资料至运营者配置的夸克网盘桥接。平台提供“Agent ＋模型额度”和“仅 Agent 月费 / 年费 / 永久”两类套餐；当前通过管理员开通，未接真实收款。商业 ChatGPT 订阅接入须取得 OpenAI 官方资格后启用。

```bash
# 桌面开发预览 / 为当前系统生成安装包
npm run desktop:dev
npm run desktop:pack

# 独立云服务：先按 services/cloud/.env.example 配置
npm ci --prefix services/cloud
npm run cloud:dev
```

```bash
# 生产构建与本机预览
npm run build
npm start

# 验证
npm test
npm run lint
npm run typecheck
```

## 已实现的工作流

| 能力 | 当前实现 |
| --- | --- |
| 职业记忆 | SQLite 持久化；分类、来源、确认状态、有效期、AI 使用许可、修正、删除和并发版本检查 |
| 能力证据 | 手动录入作品 / 项目材料、面试记录和自述；保留原文摘录、定位、技能标签与个人贡献 |
| 证据覆盖分析 | 对用户确认的岗位必需技能逐项显示材料和缺口，区分作品与自述；计数不等于能力评分 |
| 智能简历定制 | 复用 LuJie 的简历编辑、导出、JD 定制与独立版本；模型任务补充经许可的职业背景 |
| 证据定制 | `/intelligence` → “证据定制”；选择简历、已有岗位与授权证据 → app-server 调用 MCP 读取材料 → 逐项提案与来源摘录 → 用户确认 → 新简历版本；任务持久化、取消、来源失效与重复确认保护 |
| 岗位与投递 | 复用岗位档案、静态校招目录、申请进度、阶段日期和跟进记录 |
| 模拟面试 | 复用面试准备、问题生成、作答和报告；补充可用职业背景。实时逐答自适应追问尚待开发 |
| 持续成长 | 从证据缺口加入持久化任务；关联已确认、技能匹配的作品 / 面试证据后完成；证据修改或删除使关联任务重开 |
| 个性化 Agent | 新增 `read_career_memory` 工具，跨对话按需检索确认、未过期且允许用于 AI 的记录；业务写入沿用上游确认机制 |
| Codex 深度复盘 | 可选官方 SDK 适配器、结构化结果、证据 ID 校验、来源类型校验、超时、临时目录清理；需要额外模型配置 |
| 数据导出 | 职业记忆、证据与成长任务导出 JSON；这是新模块导出，不含上游全部业务数据，也不是完整备份 |

能力证据的“本人已确认”表示用户核对过材料，不表示平台独立验证了真实性。首版不会抓取仓库、运行他人代码、从技能标签推断掌握程度或自动投递。上游演示简历和岗位不会自动变成用户的能力证据。

## 建议体验顺序

1. 在“职业记忆”记录真实目标、工作偏好或约束，并按需设置有效期。
2. 在“能力证据”粘贴一段真实项目 / PR / 方案材料，写清个人贡献和来源，核对后确认。
3. 在“能力地图”填入 JD 中的必需技能，查看关联材料与证据缺口。
4. 将一个缺口加入成长计划；完成实践后保存新的作品证据并关联任务。
5. 在设置中连接模型，再进入 JD 定制、面试助手或右下角 Agent。新记录默认不发送给模型；逐条允许后才能参与个性化分析。

首次启动保留 LuJie 的演示简历、岗位和引导。可以在设置中清空上游示例；该操作不删除 TRACEFOLIO 职业记忆与证据。

## Codex 配置

在本机 `.env` 中设置以下两项并重启服务，模型名称使用账户实际可访问的型号：

```dotenv
TRACEFOLIO_CODEX_API_KEY="your-model-service-key"
TRACEFOLIO_CODEX_MODEL="your-available-model-id"
```

GitHub PAT 只用于代码仓库访问，不能当作模型密钥。适配器固定 `@openai/codex-sdk@0.167.1`，不继承开发者 Codex 登录态或 MCP 配置；使用临时工作目录、只读模式、禁用命令工具 / 网页搜索，并在结束后清理临时状态。配置隔离不替代商业环境中的容器 / 虚拟机隔离。

“证据定制”使用固定 `@openai/codex@0.167.1` 的 app-server 稳定协议与任务专用 MCP。`npm run dev` / `npm start` 自动启动独立 worker；网页断开不取消后台任务。进程中断的模型请求不会自动重放，需要用户重新创建任务。可选 `TRACEFOLIO_CODEX_BASE_URL` 必须提供与 Codex 兼容的 Responses 接口，不能直接套用任意 Chat Completions 地址。升级前运行 `npm run runtime:check`。详见 [运行与验收说明](docs/CODEX_TASKS.md)。

“生成修改提案”和“用 Codex 深度复盘”会分别触发对应的模型调用。模型服务有独立的使用条件、地域范围与成本；中国市场的默认服务应选择实际可用、经评估的供应商。开源运行时不代表模型可免费使用或能在任何地域提供服务。详见 [技术依据与来源](docs/UPSTREAM.md)。

## 数据与运行边界

- 本机职业工作台仍为单用户，旧业务表尚未加入租户隔离。独立云服务已有账号与资料所有权；登录不会自动同步本机档案。开发和生产预览命令默认仅绑定 `127.0.0.1`，公开 SaaS 仍需完成旧业务表的数据隔离。
- 默认数据在 `prisma/dev.db`。只有模型凭证采用应用层加密，职业资料和对话数据库本身没有整体加密。备份数据库时同时妥善保管 `.env`，不要把二者提交进 Git。
- “允许用于 AI”只控制新增职业记忆 / 证据模块的后续检索；上游简历和面试功能仍会使用当前任务选择的材料。
- 删除记忆或撤销许可会影响下一次检索，不会抹除已经保存的旧对话、下载文件、备份或服务商侧的历史请求。需要完整删除时应同时处理这些副本。
- 更新和删除带版本检查；证据更改会重新打开相关成长任务。模型建议不会自动升级成职业事实。
- 标签匹配是可解释的初始规则；语义检索、独立代码证据核验、自适应追问、全文检索和自动记忆提案均列入后续迭代。
