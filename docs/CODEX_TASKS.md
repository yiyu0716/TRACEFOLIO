# Codex 证据定制：运行与验收

本阶段实现一个本机单用户闭环：所选简历 + 已保存的 JD + 已确认并授权的证据 → Codex 阅读与提出修改 → 校验 → 用户核对 → 保存独立简历版本。其他聊天/面试入口仍用原有引擎。新旧效果对比按用户要求暂缓。

## 启动

需要 Node.js 22+。首次安装或更新后：

```bash
npm ci
npm run setup
npm run db:migrate
npm run runtime:check
npm run dev
```

`npm run dev` 和 `npm start` 用监督脚本启动 Next.js 与独立任务 worker；任一子进程退出时另一进程也会停止，防止界面显示在线但任务执行器已丢失。单独运行网页时，可另开终端执行 `npm run worker`。Docker 使用同样的 worker 与网页进程管理，本机仍仅暴露 127.0.0.1。

在 `.env` 配置并重启：

```dotenv
TRACEFOLIO_CODEX_API_KEY="your-model-service-key"
TRACEFOLIO_CODEX_MODEL="your-accessible-model"
# 可选，必须验证 Codex 所需 Responses 与工具语义兼容性
TRACEFOLIO_CODEX_BASE_URL=""
TRACEFOLIO_CODEX_TIMEOUT_MS="180000"
```

不借用桌面开发账户登录态，不把 GitHub PAT 当模型密钥。设置页的旧模型供应商配置不自动用于这条新 runtime。`BASE_URL` 仅影响 app-server 任务，不改变旧 SDK 复盘入口。

## 操作

1. 保存一份原简历和包含完整 JD 的目标岗位。
2. 在职业智能 → 能力证据中录入真实摘录、来源与个人贡献，核对后确认，并允许用于 AI。
3. 打开“证据定制”，选择简历、岗位和最多 10 份证据。是否参考职业记忆由本次任务明确选择，过期和未授权的记忆不会加入。
4. 点击“生成修改提案”。任务持久化，可关闭网页后从任务列表返回；详情 URL 的 `task` 参数可恢复同一任务。
5. 核对每项原文、改写、理由与原文引用。程序检查只确认结构和摘录，不能代替事实核验。
6. 勾选核对声明后保存新版本。原简历不覆盖，模型建议不写入职业事实库。

只允许改写原简历已有、非空的简介、自评、教育/工作/实习/项目 highlights 和自定义模块正文；当前不能新增经历、改身份字段、改技能列表或重排条目。证据缺口显示为待补充问题。没有可安全改写内容时，任务进入“需要补充材料”，不创建空版本；补充后创建新任务。

## 运行边界

- 网页断开：任务继续，页面轮询数据库恢复视图。
- worker / Codex 中断：租约到期后标记未完成。不会自动重跑收费请求，也不声称模型轮次可无损恢复。
- 取消：运行中发出中断并终止进程；状态竞争保证迟到结果不能发布或保存。取消不能撤销已经发生的模型用量。
- 材料变化：确认/许可/版本/有效期均重新检查。证据/记忆修改或删除会使关联任务失效；已保存简历仍保留供用户自行修正。
- 输入与历史：快照、提案和进度存在本机数据库，删除原材料不等于删除全部快照副本。
- 用量：记录 runtime 报告的 tokens 和任务耗时。费用为未知，未把 tokens 当作价格或账单。
- 隔离：临时配置、空工作区、只读模式、禁用 shell/网页搜索、限定 MCP 和最小环境变量。不等于多租户容器隔离，禁止据此公开为 SaaS。

## 测试与升级

```bash
npm test
npm run lint
npm run typecheck
npm run build
npm run runtime:check
```

固定 CLI `@openai/codex@0.167.1`、MCP SDK `1.32.2`。通过稳定 stdio 协议，不开启 `experimentalApi`，不依赖 `dynamicTools`。`runtime:check` 使用已安装 CLI 生成 schema 核对所需字段，不调用模型。它不是完整兼容性证明；升级仍应运行协议、MCP、取消、来源失效和保存幂等测试。

自动化覆盖合成材料端到端事务、来源/摘录/数字校验、许可与有效期、乐观并发、取消迟到结果、进程超时清理、真实 MCP 传输及环境隔离。另通过固定原生 CLI + 本机脚本化假 Responses 服务完成多步 MCP 闭环，核对不会暴露 shell 或多 Agent 工具。没有连接真实模型进行质量或商业费用评测，不能据此宣称 Codex 优于旧方案。
# v0.2 模型配置补充

设置页“模型连接与平台账号”中添加、选择的模型连接优先于下文环境配置。可选择 Responses，或通过单次协议适配层使用支持工具的 Chat Completions 服务；Codex 仍是主任务循环。平台模型使用账号额度，不向本机下发运营者模型密钥。任务在创建时绑定连接摘要，执行前连接变化会停止任务。环境变量配置继续兼容没有选中连接的开发模式。详见 [桌面与云服务说明](DESKTOP_CLOUD.md)。
