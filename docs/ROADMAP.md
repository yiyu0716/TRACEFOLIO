# 开发与商业验证路线图

更新时间：2026-11-11。以下是按依赖组织的计划，里程碑以验收条件推进，不表示已经实现或承诺固定上线时间。

## M0：可演示的本地底座

本次范围：导入并注明 LuJie 来源；建立 TRACEFOLIO 品牌入口；实现持久记忆、来源化证据、标签覆盖和证据驱动成长任务；接入经许可背景与可选 Codex 复盘；保留上游求职工作流。

验收：安装与迁移可重复；规则 / 数据 / 模型边界测试通过；核心页面可以实际操作；代码构建、类型和 lint 检查完成。Codex 真实服务调用需另用可访问模型与 API Key 验收。

## M1：验证技术人才的真实需求

访谈 15 人、邀请 10 人带真实材料完成一个目标岗位准备。交付清晰的项目证据清单、岗位版本简历、项目深挖问题和实践建议。记录首次完成时间、重复使用、人工纠错、用户愿意支付的金额与理由。

重点验证：用户是否愿意整理个人贡献；材料是否足以支持有意义的分析；已有简历工作流相比增加证据后是否更有用；成长功能能否产生新的真实材料。少量用户的转化率只作方向信号，保留访谈原话和样本条件。

进入下一阶段的建议门槛：至少 3 位用户实际付费试用或签署明确付费意向；多数完成者能够指出一个由证据分析发现并修正的问题。以上是团队拟定的实验门槛，需要依据试点重新调整。

## M2：把证据与面试做深

1. GitHub 只读导入，限定用户授权范围。固定 commit / PR / 文件 / 行号；先解析文本，不执行用户仓库代码。
2. 建立 Artifact、Claim、EvidenceSpan 和 EvidenceAssessment，保留自述与核验级别；支持一条能力表述对应多段材料。
3. 记忆提案、冲突提示、来源版本和用户确认。保存纠错历史，支持过期提醒、导出 / 删除及派生索引失效。
4. 让 JD 结构化必需 / 优先项、技能层级、经验、地点与约束。岗位匹配分别输出硬门槛、证据覆盖、偏好与不确定性。
5. 简历句子与证据关联，提供逐句依据、差异预览与事实核对。新增内容只能以待确认草稿进入。
6. 逐答自适应追问，区分事实澄清、工程取舍、系统设计和表达；复盘只生成记忆 / 成长提案。
7. 可复现评测集覆盖：错误归因、他人代码、过期证据、冲突记忆、缺少材料、材料提示注入、虚构成果数字与不适用的岗位要求。

验收：每条能力建议能回到具体材料；无法确认的内容明确保留不确定性；面试确实使用上一轮回答决定追问。此阶段再决定哪些长任务从单次 SDK 复盘迁到 Codex app-server。

## M3：小规模付费产品

付费前完成全部业务表的身份与租户归属、授权检查、账户恢复、删除、备份恢复与访问审计。新模块与继承模块必须一起隔离，不能只给职业记忆表添加 userId。

接入 PostgreSQL、材料对象存储、任务队列、成本日志和版本化模型配置。增加任务预算、超时、取消、限流、幂等、失败重试和恢复策略。运行时按任务隔离，模型密钥放服务端密钥管理，不依赖浏览器或共享本机配置。

上线一个清晰的岗位准备包或时限求职套餐，公开权益与额度；接入支付回调校验、权益账本、退款和超额处理。对每位付费用户计算实际贡献毛利，不先推出无限量高成本推理。

根据服务对象、部署地、模型供应商和数据流向，完成主体资质、服务条款、隐私同意、敏感职业材料处理、供应商条款和发布要求的专业核查。这里列的是待办，不作具体法律适用结论。

验收：两位用户之间任何业务数据都无法交叉读取 / 修改；重试和重复回调不重复计费；额度耗尽时不启动昂贵任务；账户删除覆盖派生文件和索引；恢复演练能够还原数据与密钥依赖。

## M4：可持续增长

在真实使用数据支持后，增加中文技术岗位模板、可选语音面试、周期复盘和长期作品成长。优先使用用户新产生的材料触发下一次有用任务，再考虑训练营 / 高校的服务协作版。机构数据授权与个人数据所有权需分别设计。

优先观察：首个岗位包完成率、无依据表述纠正率、已确认材料增量、实践完成率、一个求职周期内复用、退款、支持成本和贡献毛利。招聘转化结果用于观察关联，不直接作为 Agent 效果保证。
