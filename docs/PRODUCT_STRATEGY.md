# 产品定位与首版范围

版本：2026-11-11。面向中国市场的程序员 / AI 技术人才。这是产品决策与待验证假设，不是已获得的市场结论。

## 核心承诺

帮助用户把“我做过什么”整理为能够解释、追溯并持续积累的职业资产，再用于具体岗位的简历和面试。长期职业记忆保存用户目标、选择和约束；证据库保存支持能力表述的材料。Agent 每次使用最新、经许可的记录，不能用聊天印象代替事实。

首批用户聚焦：有 1–5 年开发经历、正在申请 AI 应用 / 后端 / 全栈岗位的人；同时允许有可展示项目的应届开发者。该范围是验证起点，避免首版同时覆盖所有行业和所有资历层级。

## 首个价值闭环

用户带来一份简历、一个目标岗位 JD 和一份真实项目材料。系统整理职业目标，逐项关联岗位要求与材料；基于已有事实定制简历，围绕项目贡献和关键取舍进行模拟面试；将缺口转成下一步实践，并用新证据验证改进。

| 阶段 | 用户结果 | 事实约束 | v0.1 状态 |
| --- | --- | --- | --- |
| 建立画像 | 背景、目标、偏好、约束可修正 | 区分未确认、已确认、过期 | 已实现手工维护 |
| 整理证据 | 每条材料有定位、摘录、个人贡献 | 作品、自述与面试记录分别标注 | 已实现手工录入；未独立核验 |
| 对照岗位 | 能看到支持材料和待补充项 | 标签关联不等于能力证明 | 已实现规则匹配 |
| 定制简历 | 同一真实经历的岗位版本 | 不编造身份、任职、项目和结果 | 复用上游并加入背景检索 |
| 项目深挖 | 能讲清“为何这样做、如何验证” | 问题与反馈要依托材料 | 上游模拟面试 + 可选 Codex 复盘；逐答追问待做 |
| 持续成长 | 下一步实践与成果可追踪 | 任务完成关联匹配技能的作品 / 面试材料 | 已实现 |

## 记忆与证据的定义

记忆包括职业背景、目标岗位、城市偏好、工作方式、时间约束和复盘反馈。来源、确认状态、有效期和模型使用许可独立存储。Agent 不能直接把一次回答永久写成用户事实；后续自动提案必须允许用户确认、纠错和拒绝。

证据必须说明材料在哪里、原文是什么、用户贡献是什么。本人提供的 URL 尚未被读取；人工确认也不等于平台独立验证。后续仓库分析需要固定 commit / PR / 文件行号，并区分仓库拥有者、提交者、协作者与真实个人贡献；仓库热度或代码行数不直接等于能力。

“长期”表示应用数据独立于一次对话、重启后仍可读取，并有修正和失效规则；不表示无限上下文、无限存储或模型能永久记住所有内容。v0.1 使用结构化数据库和有限上下文检索，尚未使用向量数据库。

## 模拟面试的后续标准

深度模拟面试必须具备岗位要求、简历版本、证据快照、问题状态和评分依据。下一轮追问由上一轮回答触发，优先澄清个人贡献、实现细节、取舍、失败和验证方法。面试评分反映这次回答的表现，不能直接改写稳定能力等级。

面试结束产生三种独立结果：用户回答的完整记录、可质疑的教练建议、待用户确认的记忆 / 证据提案。完成练习不自动证明用户已掌握技能。语音与实时音频放在文字追问闭环验证之后。

## 验收用例

1. 保存职业目标并允许用于 AI，重启后新的对话仍能检索；撤销许可、过期或删除后，后续检索不返回该记录。
2. 另一窗口修正同一记忆后，旧版本保存和删除返回冲突，不静默覆盖；同名主题不能重复创建。
3. JavaScript 证据不能覆盖 Java，C++ 不能覆盖 C；别名如 Node.js / nodejs 可归一化。没有材料的标签显示缺口。
4. 待确认、排除的证据不计入匹配；自述与作品分别展示。新增 AI 许可默认关闭。
5. 成长任务只能关联已确认、技能匹配的作品 / 面试记录；更改或删除完成依据，任务重新打开。
6. 简历和面试模型任务只获取获准背景。连接测试、简历结构提取不加载职业记忆。
7. Codex 结果引用不存在、未获准、未实际提供的证据，或把纯自述升级为作品结论时，返回错误并不采纳结果。
8. 没有配置模型也能完成记忆 → 证据 → 标签分析 → 成长任务；模型功能明确提示配置状态。

## 首版不承担的工作

暂不实现招聘网站自动登录 / 海投、代替用户面试、雇主端筛选、实时岗位聚合、第三方履历背调、Offer 保证或无上限模型调用。先验证用户是否愿意反复维护职业资产，以及这些资产是否能帮助其更准确地表达经历。

## 商业验证假设

先提供一个完整岗位周期的结果：材料核对、岗位版本简历、项目深挖、复盘和下一步实践。待验证的付费理由是更可靠、更省准备时间、可复用的职业资产和可见的改进，而不是更多生成次数。

先访谈 15 位目标用户，邀请其中 10 位带真实材料使用两周。记录材料整理时间、完成的岗位包数量、需要纠正的无依据表述、复盘后的再次使用和实际付费。用户反馈与面试通过率需分开：后者受岗位、市场和个人经历影响，早期不能声称因果提升。

可测试的报价示例：单岗位准备包 ¥59、30 天求职包 ¥99、90 天求职成长包 ¥249。以上仅是实验候选，不是市场调研结论或已上线价格。所有方案应有明确的深度分析额度、超额规则和退款边界；v0.1 没有支付或计费实现。

每个用户的贡献毛利 = 实收 − 模型推理 / 语音成本 − 存储 / 计算成本 − 支付 / 退款成本 − 人工服务成本。首先记录每次任务的 tokens、耗时和重试，按真实模型价格重算；不以开源框架免费推断推理成本为零。

对单次求职产品，更适合观察一个求职周期的完成度和下一次机会的回访。持续成长功能应以新增真实材料和实践完成证明价值，不能依靠无意义聊天维持活跃。
